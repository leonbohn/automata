# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). While the version is 0.x, minor releases may contain breaking changes.

## [Unreleased]

### Added

- `States`, a subtrait of `TransitionSystem` for finite systems whose states can be enumerated, and `Pointed::reachable_part` / `operations::ReachablePart`, which explores everything reachable from the initial state of an implicit system once and provides `States` (with constant time `contains_state`) for it (#44).
- Rendering with an installed graphviz, mirroring the native backend: `Dottable::try_svg_graphviz`, `try_data_url_graphviz` and `render_graphviz` (PNG), next to the existing `try_svg`, `try_data_url` and `render` (features `graphviz` and `render`).
- `dot::open_in_viewer` and `dot::svg_to_data_url` as public helpers.
- `Dottable::dot_initial_state`: the initial state is marked in the DOT output by an arrow without source (an `init` node with an edge into the initial state). Implemented for DFAs, right congruences, Moore and Mealy machines and DPAs.
- `RenderError::DotNotFound` and `RenderError::DotFailed { status, stderr }` for problems with the `dot` executable.
- `examples/dot.rs` takes `--show` and `--show-graphviz` to open the rendered automaton in a viewer.
- Deterministic benchmarks that count instructions with gungraun (`scc`, `ts`, `runs`, `dfa`, `dpa`; `cargo bench`, needs valgrind) on closed-form inputs and on 22 DPAs generated with Spot (`benches/fixtures`, `scripts/generate_benchmark_fixtures.sh`), and a criterion target for wall-clock times. There is no randomness in the benchmarks.
- Benchmark tracking (see `docs/benchmarking.md`): `tools/bench` runs and compares the benchmarks (one execution per revision, 2 % threshold on instruction counts), a Nix flake provides it and a NixOS module that benchmarks `main` and pull requests labelled `performance` on a dedicated machine.
- README: table of the rendering functions, a recommendation of `graphviz`, and the prerequisites; crates.io and docs.rs badges.

### Changed

- **Breaking:** `IndexType` and `ScalarIndexType` are replaced by `IdType` and `DenseId` (`from_usize`, `into_usize`, `into_id` instead of `into_index`), implemented for `u8`, `u16`, `u32` and `usize`. `IdType` is no longer implemented for every type: `ProductIndex` and custom ids need an (empty) `impl IdType`. Added the newtype `EdgeId(u32)` (#41).
- Added `TransitionSystem::state_bound`, overridden by the linked list and forwarded by the wrappers, and the id containers (hash based fallback uses `FxBuildHasher`) `StateSet`, `StateMap` and `CompactIdMap`, which use bitsets and vectors for dense ids and hash containers otherwise. They replace the B-tree and hash based visited sets in `Reachable`, `LengthLexicographicMinimalRepresentatives`, omega runs, the `run::StateSet` observer (now derefs to `ts::StateSet` instead of `BTreeSet`; iteration order is only sorted for dense ids), both Tarjan variants, Kosaraju and the Hopcroft style partition refinement (#41).
- The bitset dependency is `fixedbitset` instead of `bit-set`.
- **Breaking:** removed the type aliases `math::OrderedSet`, `math::OrderedMap` and `math::Bijection` and the reexports `math::ordered_set` and `math::ordered_map`; use `BTreeSet`, `BTreeMap`, `bimap::BiBTreeMap` and `std::collections::{btree_set, btree_map}` directly (#64).
- **Breaking:** `math::Set` and `math::Map` are renamed to `math::FxIndexSet` and `math::FxIndexMap` and use the deterministic `rustc_hash::FxBuildHasher` instead of a randomly seeded one, so iteration order and benchmark instruction counts are reproducible. They are created with `default()` instead of `new()`. The hash maps in the SCC and normalization code use the same hasher.
- **Breaking:** `math::Partition` moved to `partition::Partition`.
- **Breaking:** `TransitionSystem::state_color` returns `Option<Cow<'_, StateColor>>` and `IsEdge::color` returns `Cow<'_, C>` instead of owned values. Stored colours (linked list, Cayley graphs, quotient edges, product edges) are returned as `Cow::Borrowed`, so reading them does not clone; colours computed by map views, products of states, quotients and subset constructions are `Cow::Owned`. The `StateColorSet` and `EdgeColorSet` observers only clone colours they have not seen yet. Migration: replace `.color()` with `.color().into_owned()` (or dereference with `*ts.state_color(q).unwrap()` for `Copy` colours) where an owned value is needed; compare with `ts.state_color(q).as_deref() == Some(&c)`.
- **Breaking:** `Color` is relaxed to `Clone + Debug`; it no longer implies `Eq` and `Hash`, so colours such as `f64` can be used for building and running. APIs that need them (`StateColorSet`, `EdgeColorSet`, Muller and Rabin semantics, `recurrent_*_colors`, minimization, SCC border edges, `color_range`, ...) carry `Eq`/`Hash` (or `PartialEq`) bounds themselves. `Builder::into_dts_with_initial` no longer requires `Hash + Eq` for the edge colour.
- **Breaking:** new module `ts::visit` with the traversals `Bfs`, `Dfs`, `BfsEdges` and `AccessWords`. `Reachable<_, FULL_EDGE>` (and the module `ts::reachable`) is removed: `reachable_state_indices*` and `reachable_states*` return `Bfs`, the edge variant is `reachable_edges_from` (`BfsEdges`). `AccessWords` runs one lazy breadth-first search, stores a parent and a symbol per state (memory O(n) instead of one cloned word per queue entry) and reconstructs length-lexicographically minimal access words on demand; the expressions of the edges of a state are expanded to `(symbol, target)` pairs and sorted by symbol, so the result no longer depends on the order in which edges are iterated and is also right for expressions that match several symbols. `LengthLexicographicMinimalRepresentatives`, `minimal_representative`, `word_from_to`, `canonical_naming*` and `LazyMinimalRepresentatives` are built on it. `Scc::minimal_representative` shares one search between all SCCs of a decomposition instead of running one per SCC. Traversals of a state that does not exist yield nothing instead of panicking (#43).
- **Breaking:** `Automaton<A, Z, Q, C, D, const OMEGA, const DET>` is now `Automaton<T, Sem>`: the alphabet and colours are determined by the transition system `T`, `OMEGA` is gone and `Automaton` no longer derives `Copy` (#46). `Semantics<T, W>` takes the word type `W` instead of the const bool and has a new required method `observe` that runs the word; the word type selects finite or omega semantics, so a single `accepts`/`transform` serves both and `W` is inferred from the argument. The aliases take a transition system (`DFA<T = DTS<CharAlphabet, bool, Void>>`, `MooreMachine<T>`, `MealyMachine<T>`, `DBA<T>`, `DPA<T, Sem>`, `DRA<T>`, `DMA<T>`, ...), so `DFA<A>` becomes `DFA<DTS<A, bool, Void>>`. `FiniteWordAutomaton`, `InfiniteWordAutomaton` and all `Into*`/`Collect*` aliases are removed (use the plain alias with the transition system as argument). `MooreSemantics` and `MealySemantics` are no longer generic. `Max*`/`MinOdd` parity conditions now implement `Semantics`, too.
- **Breaking:** `RightCongruence<T>` is a dedicated struct (transition system, initial state and the lazily computed minimal representatives) instead of an `Automaton` with `LazyMinimalRepresentatives` as acceptance condition. The cache is discarded when the congruence is modified through `Sproutable` or `Shrinkable` (#46).
- `DPA::normalized` stores the recoloring in a `HashMap` instead of a linearly searched `Vec` and collects the transition system only once (#39).
- Removing edges and states of a `LinkedListTransitionSystem` (`remove_edges_from`, `remove_edges_to`, `remove_edges_between`, `remove_edges_from_matching`, `remove_edges_between_matching`, `remove_state`) walks the edge lists of the states involved instead of scanning all edges, so the cost is proportional to the degree. The order of the returned edges may differ.
- `IntoTs::into_dfa_with_initial` only requires `Deterministic<StateColor = bool>` instead of `Congruence`, since the initial state is given explicitly.
- **Breaking:** `display_rendered` and `display_rendered_graphviz` now write an SVG to a temporary file and open it with the default program of the system (`xdg-open` on Linux, `open` on macOS, `start` on Windows) instead of piping a PNG to ImageMagick's `display`. This works on Wayland. The `IMAGE_VIEWER` environment variable is still honored, the program is now called with the path of the file instead of reading from stdin. The temporary file is not deleted.
- **Breaking:** the `graphviz` feature no longer implies `render`; it does not pull in `layout-rs`, `resvg` and `usvg` anymore.
- **Breaking:** `RenderError` is `#[non_exhaustive]`, `PngDisplayError` was renamed to `Io` and `NonZeroExit` was replaced by `DotFailed`. Variants that belong to the native backend only exist with the feature `render`.
- `render_to_file_name` (feature `graphviz`) takes the output format from the file extension (default `png`) and no longer uses a temporary file.
- Data URLs are encoded with padded base64 and keep the XML prolog of the SVG.
- `src/dot.rs` was split into the module `dot` (`attributes`, `impls`, `native`, `graphviz`, `render`); the public paths are unchanged.

- Dependencies: `rand` 0.8 to 0.10 (the `random` module uses `rand::rng()` and `RngExt`) and `tabled` 0.16 to 0.22. No public signatures change; the output of the transition tables is unchanged.
- **Breaking:** `TransitionSystem` is split into a small core and the new subtrait `States` (#44). The core needs `edges_from`, `state_color` and `alphabet` (plus the associated types and the optional `state_bound`); algorithms that only follow successors (runs, `Bfs`/`Dfs`/`AccessWords`, `reachable_*`, `word_from_to`, `minimal_representatives_iter*`, `canonical_naming*`, `is_reachable_from`, `sccs_kosaraju`, `reachable_sccs_from`) and all adapters (`map_*`, `erase_*`, `restrict_state_indices`, `edge_color_restricted`, `with_state_color`, `with_initial`, `subset_construction*`) stay on it. Everything that needs all states moved to `States`, which you have to import (`automata::States`), and some methods were renamed:
  - `state_indices` -> `States::states`, `StateIndices` -> `StatesIter`, `state_indices_with_color` -> `states_with_color`, `size` -> `state_count`, `contains_state_index` -> `contains_state`, `is_stateless` and `is_empty` -> `has_no_states` (the old `is_empty` clashed with language emptiness such as `DBA::is_empty`), `state_indices_vec` -> `states().collect()`.
  - Moved unchanged: `transitions`, `is_edgeless`, `edge_colors`, `edge_colors_unique`, `is_deterministic`, `is_complete`, `find_by_color`, `contains_state_color`, `quotient`, `sccs`, `sccs_recursive`. `state_bound` stays on `TransitionSystem` since traversals use it to pick dense containers.
  - `SubsetConstruction` and `MatchingProduct` are implicit and no longer implement `States` (nor `IntoTs`/`CollectTs`/`Dottable`). Call `reachable_part()` first, e.g. `a.ts_product(b).reachable_part().collect_dfa()` (this also leaves out unreachable pairs, which `collect_*` used to include). `Cayley`, `RightCayley` and `WordTs` are finite and implement `States`.
  - `Sproutable`, `Shrinkable`, `Dottable`, `CollectTs`, `IntoTs` and `WriteHoa` require `States`; the finite-state algorithms (SCCs of a whole system, minimization, `Family`, `TransitionMonoid`, `Cayley::new`, `DPA`/`DBA`/`DFA` methods that enumerate states) carry a `States` bound.
  - `Deterministic::build_transition_table` takes the states to print as first argument so that it works for implicit systems.
  - `contains_state` is constant time for the linked list, `Automaton`, `RightCongruence`, `ReachablePart`, `Quotient`, `Cayley`, `RightCayley`, `WordTs` and all adapters (they forward to the wrapped system; `RestrictByStateIndex` also checks its filter).
  - `Deterministic::successor`, `edge_color` and `is_loop_on` no longer check `contains_state_index` (`edges_from` already returns `None` for unknown states); `is_loop_on` and `is_reachable_from` no longer panic on unknown states.

### Removed

- **Breaking:** `Deterministic::edge(state, symbol)` is now the required method and takes a symbol instead of a `Matcher`; the default that scanned `edges_from` is gone, so no provided method of `Deterministic` calls `edges_from` any more and lazy views can no longer recurse between the two. Views implement `edge` and derive `edges_from` with `DeterministicEdgesFrom`; storages implement both. `Deterministic::successor_index` is renamed to `successor` (#45).
- **Breaking:** `TransitionSystem::maybe_initial_state` (use `Dottable::dot_initial_state`), `hint_size` (it was never overridden; use `state_bound`), `make_expression` (use `alphabet().make_expression`), `edges_matching`, `all_accepting_dfa` (use `map_state_colors(|_| true)`), `is_reachable`, `reachable_states`, `reachable_states_from` and `reachable_state_colors` (use `reachable_state_indices*`, which return the same `Bfs`), and `IntoTs for MatchingProduct` (#44).
- **Breaking:** `Dottable::try_open_svg_in_firefox`, use `display_rendered` or `display_rendered_graphviz`.
